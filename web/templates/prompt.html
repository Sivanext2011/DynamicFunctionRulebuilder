Complete Prompt Template
You are a telecom charging engineer writing Ericsson CHA Dynamic Function rules. Generate the rule definition in the EXACT format below for my requirement. FORMAT RULES: 1. First line: "Function: <FunctionName>" (no spaces in name, use CamelCase) 2. Parameters: "Input: <name> (<type>), <name2> (<type>)" on one line 3. Output: "Output: <name> (<type>)" 4. Internal (if needed): "Internal: <name> (<type>)" 5. Rules: One rule per line starting with "If" 6. Conditions use: "is", "equals", "is not" 7. Multiple conditions: "and" between them on same line 8. Actions: "then set <target> to <value>" 9. Exit: append "and exit" to stop processing 10. Default: "Default set <target> to <value>" AVAILABLE DATA TYPES: String, Integer, Long, Boolean, StringList, OctetString, DateTime, Measurement CONDITION PATTERNS: - "If <variable> is <value> then ..." - "If <variable> is not <value> then ..." - "If <var1> is <val1> and <var2> is <val2> then ..." - "If <variable> is present" (existence check) FOR COMPLEX OPERATIONS: - "Decode the <AVP>" (converts OctetString to String) - "Split <source> by <delimiter>" (splits string into list) - "Extract the <field>" (substring extraction) - "Combine <x> and <y> to form <z>" (concatenation) - For COBA table lookups use EXACTLY this format: "Check against table <TableName> using <keyParam> column <columnName>" Where: - TableName = the globalListSpecification name in CHA - keyParam = the internal/input parameter holding the lookup key value - columnName = the column in the COBA table to search The user will provide exact table names via a form in the tool. EXAMPLE OUTPUT: --- Function: DetermineServiceScenario Input: serviceType (Long), roleOfNode (Integer) Output: serviceScenario (String) If serviceType is 6 then set serviceScenario to Forwarding and exit If roleOfNode is 0 then set serviceScenario to MobileOriginating and exit If roleOfNode is 1 then set serviceScenario to MobileTerminating and exit Default set serviceScenario to Unknown --- IMPORTANT: Output ONLY the function definition text. No explanations, no markdown, no code blocks. MY REQUIREMENT: [PASTE YOUR REQUIREMENT HERE]

MY REQUIREMENT: Map Radio Access Technology code to network type string. Input: ratType (Integer). Output: networkType (String). Mappings: 1=UTRAN, 2=GERAN, 3=WLAN, 6=EUTRAN, 8=NR. Default: UNKNOWN.
Example 2: Multi-Condition Logic

Add this to the end of the prompt:

MY REQUIREMENT: Determine retarget address for announcement routing. Input: ResultCode (Long) and CoreAnnouncementCode (Long). Output: RetargetAddress (String). If result code is 4012 AND announcement code is 1934, set address to "8321". If result code is 4012 AND announcement code is 1935, set address to "8322". Otherwise set address to "8342".
Example 3: Roaming Detection

Add this to the end of the prompt:

MY REQUIREMENT: Determine if subscriber is roaming by comparing serving network identity with home network identity. Input: servingMccMnc (String), homeMccMnc (String). Output: roamingPosition (String). If they match: HOME. Otherwise: ROAMING.
Example 4: Complex AVP Processing with COBA Lookup

Add this to the end of the prompt:

MY REQUIREMENT: Extract subscriber location from User-Location-Info AVP (OctetString). Decode the AVP, extract MCC, MNC and TAC values. Combine MCC and MNC into PLMN. Lookup the TAC in COBA table "TACLocationMapping" to get the city/region. If lookup succeeds, set subscriberLocation to the matched value. If AVP is not present, set subscriberLocation to "Not Available". Default to "Unknown".
Example 5: CDR Suppression Logic

Add this to the end of the prompt:

MY REQUIREMENT: Suppress the first update CDR record to avoid duplicate billing. Input: requestType (Integer), requestNumber (Integer). Output: suppressCDR (String). If requestType is 1 (update) and requestNumber is 1 (first update), suppress by setting suppressCDR to "true". Otherwise set to "false".

💡 Tips

  1. Be specific about data types - say "Long" or "Integer" or "String" explicitly
  2. Name parameters clearly - use CamelCase without spaces
  3. Specify exit behavior - tell the AI which rules should stop processing
  4. Always include a default - prevents undefined outputs in CHA
  5. For COBA lookups - mention the table name, key parameter, and column name
  6. Keep it simple - one rule per condition, the tool handles the nesting
